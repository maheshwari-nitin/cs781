\begin{abstract}
I built a compact legal language modelling pipeline and adapted it to entity extraction, rhetorical roles,
judgment prediction, statute identification, summarization and prior-case retrieval. Four foundation
architectures fit within the 50M--300M parameter limit. A 280.8M-parameter dense decoder produced the
best recorded submission in every phase, including 0.7935 judgment macro-F1 and 0.1855 retrieval
micro-F1@7. This was not a matched-budget architecture comparison: its later foundation checkpoint
had substantially more training than the alternatives. The clearest trade-offs concerned restricted
document coverage, adapter efficiency and incomplete experimental coverage. I separate finished uploads
from failed attempts, local metrics from competition scores, and implemented experiments from unexecuted
tuning proposals. An implementation diagnostic also identifies padding sensitivity in the encoder path.
\end{abstract}

\section{Introduction and Problem Description}
The project considers a legal language system that can be hosted without sending case material to an
external prediction service. The practical difficulty is not simply producing fluent legal text. A useful
system must recover exact entity boundaries, distinguish a court's reasoning from quoted precedent,
predict several applicable statutes, summarize a holding and retrieve relevant earlier cases. These tasks
need different outputs and different error checks.

The course fixes a 50M--300M foundation-model budget and requires training the foundation without loading
pretrained language-model weights. I explored a dense decoder, an encoder--decoder, a recurrent-attention
hybrid and a sparse-expert decoder. Later phases reuse those foundations in separate adapted models.
The tasks follow the course benchmark derived from Indian legal text understanding and reasoning
\cite{iltur,coursebrief}. Table~\ref{tab:tasks} states the evaluation contract.

The project examines how a compact legal language model can be adapted to tasks with different
prediction requirements. I compare foundation models and adaptation methods across exact-span
extraction, classification, generation and retrieval, with particular attention to the information
retained from long judgments. The experiments assess whether updating the full backbone or a small
set of adapter parameters gives the better task result, and identify failures that aggregate scores
can hide, such as repeated summary sentences and irrelevant retrieved cases.

\section{Data Analysis and Preprocessing}
\subsection{Sources and official splits}
The source is the official \code{Exploration-Lab/CS-781-Capstone} release. Phase 1 samples documents
from Acts, High Courts, Supreme Court and Tribunals; the preparation recipe selects 10\% of each source
and holds out 0.5\% of the selected documents. A separate full-data recipe preserves that holdout. These
are source-code settings: retained per-source counts and actual consumed-token logs are unavailable.
NER uses released folds, rhetorical roles use CL/IT train--dev files, and classification/retrieval use
their official splits. Summarization has no public dev file, so it uses a document holdout from training.

\subsection{Preprocessing}
NER retains the raw text because normalizing whitespace would move gold character offsets. Byte-level
BPE offsets are trimmed only at a token's leading whitespace before alignment. Rhetorical roles retain
the supplied sentence boundaries; they are not resegmented. Classification, summarization and retrieval
may collapse whitespace before tokenization. Duplicate statute annotations are converted to sets. Empty
retrieval text keeps its ID and receives a BOS representation rather than silently shrinking a pool.
All loaders check identifier/schema consistency; test reference fields are not training inputs.

\section{Approach and Model Evolution}
\subsection{Phase-1 foundation model}
I implemented four foundation families, summarized in Table~\ref{tab:architectures}. A follows a modern
dense causal-decoder design \cite{qwen3}: grouped-query attention, per-head query/key normalization,
rotary positions, RMS normalization and SwiGLU \cite{gqa,rope,rmsnorm,swiglu}. Each block applies attention and MLP updates through
pre-norm residual paths. Embedding and output weights are tied. B has bidirectional encoder blocks and
causal decoder blocks with cross-attention, following the encoder--decoder organization of T5
\cite{t5}. C alternates three gated DeltaNet blocks with one gated attention block \cite{gdn}.
D uses latent KV compression and shared/routed feed-forward experts, inspired by DeepSeek
\cite{deepseek}; it also exposes an optional multi-token objective.

For A, the unique-parameter calculation is explicit:
\[
N=32{,}000\!\times\!1{,}024+22\!\times\!11{,}274{,}368+1{,}024
 =280{,}805{,}120.
\]
The code also counts unique parameter tensors so tying is not double-counted. All four implementations
satisfy the stated parameter interval. The 32k byte-level BPE handles names and citations without an
out-of-vocabulary replacement requirement. Decoder pretraining predicts every next token; B predicts a
256-token continuation conditioned on a 768-token prefix. Phase-1 generation targets 128 words, using
the archived greedy recipe with repetition penalty 1.1; the exact winning dump settings were not retained.

\mainbreak
\subsection{Transfer protocol (Phases 2--7)}
Task models load a saved Phase-1 checkpoint and add a task head where needed. Feature extraction uses
an explicit hidden-state method, B's encoder, or a hook immediately before the tied LM output. The hook
avoids materializing vocabulary logits for classification and retrieval. Full adaptation trains the used
backbone parameters; partial adaptation trains the last feature blocks and final norms. In B's classifier
and retriever, unused decoder parameters are frozen. This saves optimizer work but does not physically
remove the decoder from the stored model.

The low-rank alternatives retain frozen base projections. In conventional column-vector notation,
\[
W_{\mathrm{LoRA}}=W_0+sBA,\qquad
W_{\mathrm{LoRMA}}=(I+sBA)W_0,\qquad s=\alpha/r.
\]
LoRA adds an input-space low-rank update \cite{lora}; the implemented LoRMA wrapper applies an
output-space multiplicative update, keeps the original bias separate and initializes one factor to zero
\cite{lorma}. This describes the repository implementation, not every variant in the LoRMA paper.
QLoRA uses NF4 frozen base projections with floating-point adapters; tied embeddings/output remain
unquantized \cite{qlora}. Its implementation is restricted to A.

\subsection{Phase 2 - Legal NER}
NER is token classification with BIO labels for the 12 entity types. Gold character intervals are aligned
to tokenizer offsets; predicted BIO sequences are reconstructed into exclusive-end character spans in
the unchanged document. Overlapping windows use a deterministic owner rule: more left context for
causal models, and more central placement for bidirectional encoders. Argmax and constrained BIO
Viterbi decoding are implemented. An oracle reconstruction check exposes the ceiling imposed by token
boundaries and overlapping spans. Its measured value was not retained, so I do not report one.

\subsection{Phase 3 - Rhetorical role prediction}
The role classifier pools the token interval of each supplied sentence into 13 label logits. A document
mode supplies neighboring sentences through overlapping windows; a sentence mode is also available.
CL and IT are trained jointly in the archived recipe and evaluated by domain as well as jointly. A long
sentence is capped to fit inside at least one window. No document-level CRF is used. Synthetic-generation
utilities exist in the working repository, but I confirmed that their documents were not used in training.

\subsection{Phase 4 - Court judgment prediction}
The classifier reads four 512-token chunks from the judgment's end, mean-pools tokens and chunks,
and predicts two logits with cross-entropy. The recorded runs use a fixed 0.5 decision threshold;
balanced training weights address the observed 59\%/41\% class split in the saved KD configuration.
Mean, max and learned chunk attention are implemented, but the local full/LoRMA/KD rows change more
than one factor. They are variant comparisons, not isolated tests of chunk aggregation.

\mainbreak
\subsection{Phase 5 - Legal statute identification}
LSI reuses the document classifier with one output per observed statute. Independent sigmoids are
necessary: mutually exclusive softmax predictions would contradict documents with several correct IDs.
Training minimizes
\[
\mathcal L_{\mathrm{LSI}}=-\frac1{BK}\sum_{b,k}
\{y_{bk}\log\sigma(z_{bk})+(1-y_{bk})\log[1-\sigma(z_{bk})]\}.
\]
The recorded configuration uses four spread 512-token chunks and a fixed 0.5 threshold. Optional positive
weights and dev-calibrated global/per-label thresholds are implemented but are not credited as completed
improvements. The label-to-column map is persisted even though the observed IDs happen to be contiguous.
KD for D uses independent Bernoulli teacher targets rather than a categorical distribution over statutes.
Its student is genuinely smaller in total backbone parameters than A.

\subsection{Phase 6 - Abstractive summarization}
Decoder models receive document markers, selected source tokens and the target summary; prompt labels
are masked. B uses encoder inputs and a BOS-shifted target in its decoder. The objective is
\[
\mathcal L_{\mathrm{summ}}=-\sum_{t=1}^{T_y}\log p_\theta(y_t\mid x,y_{<t}),
\]
including the end token. The saved recipe budgets 640 source tokens, including markers, and 256 target
tokens. Reference targets exceeding that budget are truncated before appending EOT. Inference permits
EOT after 16 generated tokens and caps generation at 256. It does not inherit Phase 1's fixed word count.
The recorded runs use greedy decoding without a repetition penalty or n-gram ban. A reproducible holdout
groups duplicate normalized documents together; metrics are computed on a saved subset of 32 of the
350 held-out documents. RoBERTa-large supplies BERTScore only, never training or teacher targets
\cite{bertscore}. The local scorer hash is retained in the appendix.

\subsection{Phase 7 - Prior Case Retrieval (PCR)}
A shared encoder pools tokens and chunks, then L2-normalizes the document vector. Cosine similarity
provides the ranking score. The recorded run selects first/last context totaling two 256-token chunks.
Each training query uses up to two positives and four fixed random negatives from its training pool;
all known positives are excluded from negatives. With positive set $P_q$ and sampled set $C_q$,
\[
\mathcal L_q=-\frac1{|P_q|}\sum_{p\in P_q}\log
\frac{\exp(s(q,p)/\tau)}{\sum_{c\in C_q}\exp(s(q,c)/\tau)},\qquad\tau=0.05.
\]
Dev/test search uses the complete corresponding candidate pool, with no mixing across splits. Ten
training queries have no positives and are skipped; all 118 dev and 237 test queries are retained.
Retrieval KD and longer-training candidates are implemented but have no completed result in the supplied
record. This distinction matters when auditing the mandatory KD requirement.

\section{Experiments and Implementation Details}
\subsection{Training protocol}
Only free Kaggle compute was used for training. Under this constraint, I could complete the planned
full pretraining run only for model A; the other foundations were adapted from partially pretrained
checkpoints. This allowed me to implement and evaluate all seven task pipelines, but the resulting
comparison reflects both architecture and pretraining progress. AdamW, gradient clipping and fixed
random seeds were used throughout. Phase 1 uses warmup--stable--decay, while the later loops use
warmup followed by linear decay. Appendix~\ref{app:configs} distinguishes saved settings from
reconstructed configurations.

\subsection{Local evaluation}
NER selects a training-document holdout; roles, judgment, LSI and PCR use official dev labels.
Summarization uses the internal holdout described above. Local BERTScore settings are not guaranteed to
match the competition scorer; ROUGE reports reference overlap \cite{rouge}. Checkpoints are selected
by the task metric, not test labels. Classification thresholds and decoding options are saved for inference.
Phase 1 supports optimizer resume; the later snapshots are inference checkpoints rather than exact
optimizer resumes. Original Phase-1 weights remain external to the submitted code archive.

\subsection{Ablations and controlled comparisons}
The archive supports comparisons, but few single-factor ablations. A's full-data descendant versus
shorter-trained B/C changes both architecture and training. Full versus LoRMA changes the trainable
parameter set, sometimes pooling and budget as well. The later 30-epoch A recipe, resampled/hard-negative
options and larger retrieval context are unexecuted proposals in this record, not evidence of a gain.
I report those limits rather than converting planned settings into experimental findings.

\section{Error Analysis and Discussion}
\subsection{Phase-wise failure modes}
B is the clearest failed attempt: its NER score is 0.0006 and it trails A on every recorded phase.
There are three concrete issues to separate. First, B received far fewer pretraining updates. Second,
its prefix objective supervises only 256 positions per 1,024-token window, whereas A supervises every
next-token position. Third, downstream feature calls pass no padding mask to B's bidirectional encoder.
Right-padding tokens can therefore affect otherwise valid token representations. These observations
support investigating B's training and interface, not dismissing encoder--decoder models in general.

A controlled implementation check uses two-layer, width-32 random models, not competition weights.
Appending eight PAD tokens changes B's original-token features by relative L2 0.3133; A's change is
$5.77\!\times\!10^{-8}$. This confirms padding sensitivity in that code path. It does not quantify how
much of B's final NER failure it caused. Appendix~\ref{app:padding} gives the exact test and its limits.

The judgment KD trace peaks at dev macro-F1 0.6407 at step 9,000, then ends at 0.6361. Keeping the best

The summarization preview contains repeated sentences rather than merely low overlap. One test preview
repeats ``He was found guilty of the charge framed against him.'' 17 times in 229 words. The settings
use no repetition penalty and permit 256 new tokens; a high BERTScore does not remove this defect.
PCR also exposes a concrete retrieval error: query \code{0000035468} ranks its own ID first, while the
displayed dev row has zero hits against 15 references. Self-matching consumes a slot in this example.
The same pattern appears in the other displayed previews and should be tested with explicit self-exclusion.

\mainbreak
\subsection{What the metrics do not measure}
BERTScore measures similarity in an evaluator's representation, and ROUGE measures reference overlap.
Neither guarantees that a generated holding, date or statute is legally correct. Strict NER scoring can
reject a nearly correct entity because one character is misplaced. Conversely, a perfect schema does not
make a prediction useful. The project needs both structural validation and task evaluation, followed by
human legal review before any decision-making use.

The retrieval cutoff also has an intrinsic coverage limit. One displayed dev query has 92 relevant cases;
even seven correct outputs would yield recall only $7/92=0.0761$ for that query. This does not explain
away A's low overall recall, but it shows why the complete gold-set size must remain visible. I do not
average the seven phase scores into one number: they measure different objects under different scales.

\subsection{Limitations and what I would do next}
A is the strongest recorded model, but its representation of long cases still depends on narrow
selected windows. The immediate retrieval follow-up is a longer training budget with refreshed negatives, dev-best selection and a named
baseline-preserving comparison. Its planned 30 epochs could raise the 817-query, batch-32 schedule from
78 to about 780 updates. No improved score from that proposal is reported here.

For B, the next test should first pass attention masks correctly and compare pretrained models at matched
continuation-tail loss or training budget. For generation, repeat controls and a target-length study should
precede a larger backbone. For LSI, threshold calibration and complete per-label support/F1 should be
logged. For PCR, excluding non-relevant self-matches is a direct implementation ablation. These are
specific tests of the observed failures, not claims that they will necessarily improve hidden-test scores.

\subsection{Surprising findings}
Parameter efficiency did not reliably preserve task quality in this record. A's judgment LoRMA result is
far below full adaptation, although it changes much less of the model. Summarization gives a more useful
counterpoint: A's LoRA run uses about 1.14\% trainable parameters and remains the best recorded family.
The contrast suggests that adaptation quality is task- and setup-dependent; the experiments do not
support a blanket claim that low-rank updates replace full adaptation.

\section{Conclusion}
The implemented system covers all seven task interfaces with a shared set of compact foundations and
separate task adaptations. Its most defensible result is empirical: the extensively trained dense A
checkpoint is the strongest recorded model across the seven phases. Its main remaining limitation is restricted document coverage. B's poor results expose weaknesses in this
particular training and feature-extraction setup, including a reproducible padding defect, rather than a
general failure of encoder--decoder modelling.

The submission also records what remains unresolved: incomplete mandatory experiment coverage,
unretained winning-run settings in early phases, repetitive summaries, self-matches in retrieval and the
absence of human legal evaluation. Those limits determine how much can be concluded from the scores.
